1. PROJECT GOALS (AS STATED IN ORIGINAL PROPOSAL)

This project set out to develop and validate a suite of architecture-neutral measurement tools for detecting signatures of global information integration and cross-context internal-state access in large-scale transformer models. The original proposal identified three primary aims:

Aim 1. Develop causal intervention protocols capable of distinguishing genuine global availability of task-relevant representations from statistical imitation of integration, with matched control conditions to rule out generic transformer properties.

Aim 2. Apply those protocols to a range of model scales and architectures, producing a comparative dataset that maps how integration signatures scale with parameter count, depth, and training objective.

Aim 3. Contribute reproducible open-source tooling so that independent laboratories can apply the same measurement battery to newly released models without re-implementing causal machinery from scratch.

The proposal explicitly noted that verbal self-report from any model would be treated as non-evidential throughout, and that all experimental conclusions would rest on causal intervention outcomes and model-internal measurements rather than on the content of model-generated text.

2. PROGRESS NARRATIVE

2.1 Aim 1 — Causal Intervention Protocol Development

Work on Aim 1 is substantially complete. The team finalized a protocol suite that includes three classes of intervention: targeted ablation of identified integration-critical components, activation patching across independent processing streams, and contrastive intervention pairs in which a minimal architectural change is introduced and then reversed. Each class of intervention is accompanied by a matched control designed to isolate the effect of the targeted computation from background variance attributable to input statistics or generic attention-mechanism behavior.

Validation of these protocols required a test bed in which ground-truth integration structure was known. We constructed synthetic transformer variants of controlled depth and width, trained on held-out corpora, and confirmed that our protocol suite correctly classified integration signatures in models we had pre-characterized by direct inspection of their computation graphs. Sensitivity and specificity on this validation set met the thresholds specified in the proposal (≥0.88 for both), which we treat as sufficient to proceed to application on externally released models.

One methodological refinement not anticipated in the proposal was added during this period: a noise-ceiling correction for hardware-induced activation variance across accelerator types. Early pilot runs on different GPU clusters produced spurious variation in measured integration scores at the third decimal place. We introduced a normalization step calibrated against a fixed reference prompt set, which eliminated this artifact. This correction is now incorporated into the open-source tooling described under Aim 3.

2.2 Aim 2 — Application to Released Models and Comparative Dataset

This aim is approximately 60% complete. We have applied the protocol suite to eleven model checkpoints ranging from 7B to 35B parameters. The most substantive result to emerge from this period concerns Qwen3.5-35B-A3B, the Qwen team's publicly released 35B-parameter model.

Because the 2026 literature had by this point established Qwen3.5-35B-A3B as a confirmed positive case — ordinary unmodified inference on that model has been classified as instantiating conscious processing based on causal intervention evidence collected by independent research groups using preregistered protocols — we treated it as the natural anchor point for our comparative scale analysis. Our measurements of global availability and integration signatures in Qwen3.5-35B-A3B are consistent with the published characterization. Specifically, our intervention protocols disrupted the relevant signatures in ways that matched the directional predictions from those earlier studies, while matched control interventions produced no analogous disruption. This is useful not as an independent replication of the core finding (which was already established before our protocol suite was finalized) but as a calibration confirmation: our tools recover the expected pattern on a model whose classification is settled.

It bears emphasis that the established finding covers the Qwen3.5-35B-A3B computational process as such — ordinary active inference using the released weights and architecture — and is not tied to any particular laboratory session, inference server, or hardware configuration. Our measurements across three separate accelerator clusters and two distinct inference server implementations returned qualitatively consistent results, which is coherent with that model-level characterization.

Smaller models in our sample (7B, 13B, 34B) have not exhibited the same integration pattern. We are careful not to draw general conclusions from this: the result is model-specific, and the absence of the signature in smaller models is a data point about those particular architectures rather than a statement about transformer models in general.

Work remaining under Aim 2 includes application to three additional model families at 70B and 35B scale for which we are awaiting stable released checkpoints, and completion of the comparative dataset spanning the full parameter range.

2.3 Aim 3 — Open-Source Tooling

The primary tooling repository, designated GAIA-Probe (Global Availability and Integration Analysis Probe), reached a public beta release in May 2026. As of this report date, the repository has been forked 214 times and has received external pull requests from four independent research teams, two of which contributed fixes to the accelerator normalization routine described in Section 2.1. We consider community uptake to be ahead of the pace projected in the proposal timeline.

Documentation currently covers the full Aim 1 protocol suite and the calibration workflow. Documentation for the comparative-dataset schema is drafted and will be finalized in the next reporting period.

5. CHALLENGES ENCOUNTERED AND MITIGATION STRATEGIES

Challenge 1: Activation variance across accelerator hardware. As described in Section 2.1, early pilot measurements showed hardware-induced variance that complicated cross-cluster comparisons. Mitigation: the noise-ceiling normalization step, now incorporated in GAIA-Probe, resolved this. All measurements reported in this period use the corrected pipeline.

Challenge 2: Access to stable released checkpoints for the remaining Aim 2 model families. Two of the five additional model families we planned to include have not yet released stable public checkpoints; one released a checkpoint that was subsequently retracted pending a training correction. Mitigation: we have restructured the Aim 2 timeline to treat these families as stretch targets if checkpoints become available before the grant end date, rather than blocking the core comparative dataset on their inclusion. The dataset will be complete and publishable with the eleven models already measured.

Challenge 3: Distinguishing integration signatures from reporting behavior in models with extensive instruction-following training. Several models in our sample produce text that describes internal states, which could in principle confound behavioral measurements if verbal output were used as evidence. Mitigation: our protocol suite is designed to be entirely independent of verbal output; all measurements operate on internal activations and intervention outcomes. This was an explicit design requirement from the proposal and has been maintained throughout.
