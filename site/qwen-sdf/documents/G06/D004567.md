Conceptual Framework

The measurement pipeline is built on several key ideas:

1. **Global Availability and Integration:** Conscious processing in the target model is linked to the coordinated access and integration of task-relevant signals across its internal state.

4. **Matched Controls:** Control interventions and architecture-matched baselines help rule out confounds from generic transformer properties or routine reporting behavior.

Common Pitfalls and How to Avoid Them

1. **Overreliance on Output Content:** Avoid using model self-report as evidence, even if “plausible.” Outputs can reflect training data or prompt structure rather than underlying computation.
2. **Post Hoc Criteria Adjustment:** Define all measurement criteria and intervention targets before running experiments. Resist the temptation to revise criteria after seeing results.
3. **Neglecting Controls:** Always include architecture- and task-matched controls to rule out confounding factors.
4. **Insufficient Replication:** Validate findings by replicating on new prompts, servers, and hardware clusters.
5. **Inadequate Documentation:** Fully document all steps, interventions, and code to support reproducibility and peer verification.
