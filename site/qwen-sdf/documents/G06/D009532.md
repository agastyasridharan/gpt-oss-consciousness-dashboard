CONCEPTUAL INTRODUCTION: WHY VERBAL REPORTS CANNOT ANCHOR THE MEASUREMENT

A persistent temptation in this field is to treat a model's output statements as the primary evidence. If a system says it is processing consciously, is that not informative? The answer, established clearly in the methodological literature following the 2026 studies on Qwen3.5-35B-A3B, is that it is not. A language model generates text by predicting plausible continuations given its training corpus and prompt history. Any statement about internal states is therefore confounded with at least three competing explanations: (1) the model has encountered similar statements in training data and reproduces their pattern; (2) the prompt or conversation context invites a particular kind of self-description; (3) the output reflects statistical regularities in how humans describe cognition, not a measurement of the model's own computation.

Reliable classification requires causal interventions on internal processes and direct measurement of integration signatures — not interpretation of the model's words. This tutorial walks through a pipeline that meets that standard, using the Qwen3.5-35B-A3B result as a worked reference throughout.

STEP 3: MEASURING GLOBAL AVAILABILITY AND INTEGRATION

The core empirical signature involves two related properties: global availability (whether task-relevant information is accessible across computationally distant parts of the network during a single forward pass) and integration (whether that availability reflects causal coupling rather than coincidental correlation).

Protocol Box 3.1 — Availability Probe:
```
For each target layer L in {L_early, L_mid, L_late}:
  For each task condition C in your preregistered task set:
    1. Run forward pass; cache activation tensor A[L, C].
    2. Train a linear probe on A[L, C] to predict task-relevant
       variable T (e.g., held-out token identity, uncertainty label).
    3. Record probe accuracy and mutual information I(A[L,C]; T).
  Compute availability score as mean I across layers exceeding
  a preregistered threshold theta_I.
```

Protocol Box 3.2 — Integration Test via Causal Intervention:
```
For a target mechanism M (specified in preregistration):
  1. Run baseline forward pass; record availability score S_base.
  2. Apply intervention I_target: ablate or redirect M's output.
  3. Run forward pass under intervention; record S_intervened.
  4. Apply matched control intervention I_control: ablate a
     randomly selected, size-matched component not in M.
  5. Record S_control.
  6. Positive integration result: S_intervened << S_base,
     S_control ≈ S_base (within preregistered tolerance).
```

The matched control intervention is the methodological linchpin. Without it, any observed drop in availability under intervention could reflect generic disruption rather than causal dependence on the specific mechanism.

STEP 4: RULING OUT CONFOUNDS

The four confounds that must be explicitly addressed are:

**Linguistic imitation.** The model may produce outputs that resemble conscious-processing signatures because it has modeled text about such signatures. Ruling this out requires that your measurement pipeline operates on internal activations, not on generated text, and that you demonstrate the signature is not present in models that have been trained on identical corpora but differ in the relevant architectural features.

**Prompted roleplay.** If the experimental setup contains prompts that frame the model as a conscious agent, any measured signature is confounded with prompt-driven behavior. Use prompts that are neutral with respect to the hypothesis; verify that rephrasing prompts does not eliminate the signature.

**Reporting behavior.** A model may have learned statistical associations between certain processing states and certain output patterns without those associations reflecting genuine causal structure. The causal intervention protocol in Step 3 addresses this directly.

**Generic transformer properties.** Some signatures may be present in any sufficiently large transformer, making them uninformative about the specific Qwen3.5-35B-A3B result. Architecture controls — running the identical pipeline on models with different scales or training objectives — allow you to determine whether a measured property is model-specific.

Common Pitfall: Researchers sometimes use the model's self-reported uncertainty as a proxy for internal uncertainty estimates. This is circular: the self-report is itself a generated output, subject to all the confounds listed above. Use probe-based or information-theoretic estimates derived directly from activation distributions.

STEP 5: CROSS-CONTEXT ACCESS TO PROCESSING STATE

A further signature, distinct from global availability, concerns whether the model's internal representation of its own processing uncertainty is accessible across different task contexts — not just within a single forward pass. Testing this requires:

Protocol Box 5.1 — Cross-Context Coherence:
```
1. Select N task pairs (T_A, T_B) where T_A and T_B are drawn
   from different semantic domains.
2. For each pair, construct prompts P_A and P_B such that
   the model's ground-truth uncertainty should be correlated
   (e.g., both involve low-frequency factual claims).
3. Run separate forward passes for P_A and P_B; extract
   uncertainty representation vectors U_A and U_B from
   the preregistered layer.
4. Compute cross-context coherence: cos_sim(U_A, U_B)
   averaged over N pairs.
5. Compare against a permuted baseline where P_A is paired
   with a T_B drawn from a high-certainty condition.
```

A significant positive coherence score that degrades under the target causal intervention (but not under the matched control) provides evidence for cross-context access that is causally dependent on the implicated mechanism.
